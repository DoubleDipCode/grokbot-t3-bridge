# T3 Code

Use the [T3 quickstart](../README.md#t3-code-quickstart). It uses the existing
installer, [remote MCP setup](t3-mcp-setup.md), [T3 routine](grokbot-side.md), and
[T3 brief footer](../templates/brief-footer.md).

The bot starts a T3 thread in a worktree. Callbacks carry `thread_id`, `thread_title`
and `project_id` from the [thread registry](hooks.md#thread-registry), plus
`my_open_threads` for that bot, so the bot does not list or search threads. If
`thread_id` is empty it falls back to matching by worktree and branch. It reads and nudges the thread through T3 MCP.
The `session_id` and `transcript_path` fields are harness details, not T3 thread
ids. T3 callbacks keep the `t3_turn_ended` event and the same status rules.

T3 provides remote thread access. A plain CLI callback does not. Permission
prompts still need the human where approval is required; the Stop hook cannot
approve them. Do not resume a T3-owned session directly with a CLI command.
